# 神数条文库数据来源（`src/lib/tieshen/data/*.json`）

本目录只放**可核对来源与许可**的神数索引表与条文断词，禁止手工新增、改写或"补全"条文。

### 为什么要单独落一个数据文件
- 该仓库把 14 张索引表与 12000 条条文断词打包成 `js/db-data.js`（497 KB）。本仓只取其**数据**（`tables` / `rule_tables` /
  `HEXAGRAM_MAP` / `HEXAGRAM_DETAIL_MAP` / `DESTINY_DATA` / `LIUNIAN_*` / `MARKER_TABLE` / `LETTER_TABLE` /
  `DATA_BY_LETTER` / `FORTUNE_DUANYU_MAP`），重排为下面 4 个 JSON，未复制其任何算法代码。
- `DATA_BY_CORRECTION` 与 `CORRECTION_TO_LETTER` 未单独落盘：它们可由 `DATA_BY_LETTER` 的行序（同一「条文校正数+岁数」
  取**末次出现**）推出，已用上游 `db-data.js` 逐键比对一致（1493 键），见 `data.ts` 的 `deriveCorrectionMaps`。

| 文件 | 内容 |
| --- | --- |
| `tables.json` | 14-1/14-2（月表、时支表）、14-3（五音表）、14-4（五音数）、14-5（日命表）、14-6（时运表） |
| `rules.json` | 14-7（考刻规则表）、14-8/14-9（卦名简表/详表）、14-10（本命条文偏移表） |
| `liunian.json` | 14-11-1/14-11-2（流年起始/流年五音序列）、14-12（流年标记）、14-13（流年字母）、14-14（字母×岁数→条文基加数） |
| `tiaowen.json` | `List.csv` 条文断词 12000 条，按「年龄⇥断词」单串存放，编号自 1001 起连续推出 |

## 未接入（本仓不生成对应条文）

- **邵子神数**（通行 6144 条谱）：条文本体与「生辰 → 编号」推算法均未获可用来源。
  - 检索面：`Horace-Maxwell/horosa-skill` 等实现为 **AGPL-3.0**（不用）；GitHub 上其它含邵子资料的仓库
    （`taozi9999/Divination`、`x3747991-ship-it/tieban-shenshu-skillpack`）**无 LICENSE**（不用）；
    维基文库、识典古籍、ctext 均**没有**《邵子神数》全文（非四库收录，仅民间抄本）；archive.org 无可核验全文；
    规则描述只出现在版权书籍/课程讲义（《陈抟神数秘旨 · 正统邵子神数》、周通新《邵子神數》2018、商业排盘站点）。
  - 因此本仓**只登记编号空间**（`data.ts` 的 `SHAOZI_SHENSHU_SOURCE` / `volumeOfShaoziTiaowen` /
    `isShaoziShenshuNumber` / `createShaoziShenshuLibrary`），并把导入通道（`importTieshenTiaowen`）留出；
    不推算、不生成邵子条文。
  - 编号空间（结构属事实性描述，可核验）：条文号 **1111–12888**，共 **6144** 条；十二部集按千位
    子集 1000 / 丑集 2000 / … / 亥集 12000，每集 512 条（先天八卦八类 × 64 卦）。
- **六亲条文（父母宫 / 兄弟宫 / 夫妻宫 / 子女宫 → 条文字号）**：上游只有「按断词关键词把断语归入六亲」的
  现代启发式（`main.py` `_build_six_qin_data`，且其参照实现的 Step 9 已注释停用），**不是**编号规则；
  传统「宫位 → 条文字号」推算法未获可核验来源，本仓不采用、不实现。
- **太玄数 / 配卦 / 洛书数**：已按可核验来源实现为**对照取数**（`rules.ts`：`TAIXUAN_NUMBER`、
  `TIAN_GAN_TO_GUA`、`DI_ZHI_TO_GUA`、`qushuOfPillar` 等）——
  来源为上游 Apache-2.0 `main.py`「4. 太玄数（核心取数体系）」（`TAIXUAN_NUMBER` / `TIAN_GAN_TO_GUA` /
  `DI_ZHI_TO_GUA`）与传统公有领域歌诀《太玄配数诀》《天干配卦》《地支配卦》。
  但「取数 → 条文编号」的完整规则未获可核验来源，故**未接入条文链**，面板只作对照呈现。
- **12000 条以外的通行「12000 条歌诀」异本、扫描件、OCR 文本**：一律不接入。

## 上游表缺口的逐项核验（2026-10）

逐键比对上游 `js/db-data.js`（commit `18ee6680`）后确认：本仓 `tables` / `rule_tables` / `HEXAGRAM_MAP` /
`HEXAGRAM_DETAIL_MAP` / `DESTINY_DATA` / `LIUNIAN_*` / `MARKER_TABLE` / `LETTER_TABLE` / `DATA_BY_LETTER`
及由 `DATA_BY_LETTER` 推出的 `DATA_BY_CORRECTION` / `CORRECTION_TO_LETTER`（各 1493 键）与 12000 条断词
**逐键取值完全一致**，本仓推导无偏差。面板上的两类空白均为**上游表缺口**：

1. **卦名「上游表未覆盖」**：14-8 简表（`HEXAGRAM_MAP`）在本命数 181–930 内缺 24 行，集合为
   `199,219,229,249,259,278,289,309,319,353,383,442,485,515,575,605,655,685,715,745,775,817,847,877`；
   14-9 详表只登记「初刻 / 正刻」两栏，而查表用的是八刻刻名，故一刻…六刻时用不到详表、退到简表，
   落在这 24 个本命数上即未匹配。（本命数恒在 181–930，不会越界。）
2. **流年「上游表未覆盖」**：14-14 明细表（`DATA_BY_LETTER`）为稀疏表，只登记部分（字母，岁数）组合。
   全表口径下，偶数岁 **106 与 108** 任何字母都无行；此外 88 / 96 / 99 / 100 / 102 / 103 / 104 / 105 / 107
   等岁在部分字母下缺行。故不同命盘的空白岁集合不同：如 `1990-05-20 08:30 男` 命中 100/108，
   未覆盖岁为 `88, 99, 100, 102, 104, 105, 106, 108`，缺口类型全部是「14-14 未登记」。

（上游 `main.py` / `js/tieban.js` 与本仓在卦名与流年的取表口径上一致；上述缺口照缺呈现，不补造。）

## 第五轮：E（非幂等 GET 轮换令牌）+ 生产构建验证

### 先确认了构建

`CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build`（webpack 生产构建）**通过**，A/Z/AB/AD/V 全部改动在内。以后在本仓跑 `npm run build` 都要带这个环境变量，否则 `.next/` 清理会被 `node-safe-delete-shim.cjs` 拦下（`CODEBUDDY_SAFE_DELETE_BULK_CONFIRM_REQUIRED`，阈值 50 / 作用域 turn）。

### E 的实际严重度比报告写的更高

报告原文："GET 可能被预取/缓存"。实际读代码：这个 GET 会把平台**轮换后的新 refresh token 写进 cookie**，而预取请求的响应浏览器通常不落盘 → cookie 里留旧 token、平台上旧 token 已作废 → **一次预取 = 一次登出**。并发两个 GET 也会互相踢。

### 动手前必须先确认的既有设计

`src/lib/platform/session.ts` 的 `loadPlatformSession()` **每次读取都主动抹掉 localStorage 里的 token**（`access_token: ""`, `refresh_token: ""`）。所以：
- token 只活在 httpOnly cookie 里 → 轮换**只能**在服务端做，挪不到客户端；
- GET **不能**返回 refresh token，否则把刚加固掉的东西还回去。

### 改法

| 文件 | 动作 |
|---|---|
| `src/lib/platform/bridge.ts` | **新增**：bridge cookie 名常量 + `isBridgeToken` / `readRequestCookie` / `readResponseCookie` / `setBridgeCookies` / `clearBridgeCookies` |
| `api/platform/session/refresh/route.ts` | **新增**：`POST` 承载轮换（逻辑自原 GET 整体搬移，含 `ssp_refresh` 缺失时回退旧 token） |
| `api/platform/session/route.ts` | `GET` 改**纯读**（不调平台、不写 cookie、只回 access + csrf）；`PUT`/`POST`/`DELETE` 行为不变，改用共享 helper |
| `lib/platform/browser.ts` | 唯一调用方改打 `POST /api/platform/session/refresh` |
| `lib/platform/server.ts` | 别名表键改引用 `bridge.ts` 常量，消漂移 |

- 不能放 `POST /session`：那个已被外部 web-sdk 的「把 body 里 token 对装进 cookie」占用，语义不同。
- `GET` 保留为纯读（不删）：删了旧客户端包会吃 405；纯读至少能降级成"重新登录"。它在本仓库内**暂无调用方**，是有意的。
- 没做"先试 GET 401 再 POST"的优化：access cookie 活着但被平台吊销时，`me()` 401，而客户端 refresh 分支拿的是空 `refresh_token`，必然失败。先保持行为逐字一致，只修安全面。

### D 重新定级（不修）

原描述指的方向对，但可利用面更小，而且有个关键细节：**这条路径的 token 来自 body，不来自 cookie，所以 `SameSite=Lax` 帮不上忙**（Lax 管的是"跨站请求是否携带 cookie"，且它本来就拦住了跨站 POST——唯一缺口是 Chrome 对 2 分钟内新设 cookie 的 Lax+POST 干预）。攻击者页面用顶层导航 `<form method=POST>` 打到本域，响应的 `Set-Cookie` 属第一方上下文，会被写入 → 能把受害者 cookie 覆盖成攻击者的。

但那是"攻击者把自己的会话塞给受害者"，不是"拿到受害者的会话"。**属可用性层面，不是权益泄露。** 结论：降级，不单独修，等 `bridge.ts` 这层再加写接口时统一加 Origin 校验。

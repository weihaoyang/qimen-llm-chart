# 删死代码：判定、证明、以及脚本会怎么骗你

从 qmdj 的「退役 shengtian 产品面」两批（附录二十四/二十五）里提炼。**这里的东西都是实测踩出来的**，
不是推的。

## 一、判定：谁在「运行」它，不是谁在「测」它

- **覆盖率不区分「被测」和「可达」**。实测：`decision-tree-panel.test.ts` 测的三个纯函数，唯一消费者
  就是那个不可达的组件 —— 测试全绿，没有任何用户路径能到达它。**一条绿测试可以把死代码钉在原地。**
- **可达性必须证明，不能假设**：查守卫依赖的 prop → 哪个路由传了什么值 → 入口组件有没有被 import
  → `/` 是不是 redirect → 实际渲染出来的文案里有没有它。实测四条一起才敢说「不可达」。
- **删组件和删它的测试必须同时做**：只删组件 = 留下给死代码背书的绿测试；只删测试 = 留下没人用的纯函数。
  删完 `tsc` 立刻 0 是「没有其它消费者」的直接证据。
- **删组件不能顺带删管线**：组件死了，它背后的数据管线可能还被导出/AI 载荷用着（实测两批都撞到）。
- **产品意图判断要问人**：「这个功能是退役了还是计划中？」不是机械清理。

## 二、大重构：先建差分 oracle，再动手

当目标组件的测试只有 1 个断言时，「改完测试全绿」什么都证明不了。

```
1. 临时测试把目标在 N 个可达状态下的 DOM 落盘（数字折成 0，其余逐字保留）
2. 跑一次 → before；同时做稳定性自检：同一状态抓两次必须逐字相等
3. 改代码
4. 再跑 → after
5. 逐状态 diff
```

- 状态要覆盖全：默认态 + 每个 tab/variant/开关 + 弹层打开态。实测 10 个状态才够。
- **稳定性自检必须覆盖「比较所用的全部维度」**：实测「同一次运行内两次抓取相等」却**跨运行不等**
  （框架每次挂载生成随机 `data-uuid`）。第一次 diff 报「10 个全 DIFFERS」，逐字看只差那个 uuid。
  **一次自检通过 ≠ 跨进程可比。**
- **前后用同一个 mock**：依赖只能在打包器里渲染的 vendor 文件时（实测一个 `.jsx` 在 vitest 下抛
  `ReferenceError: React is not defined`），前后都 mock 它，差分依然有效。
- oracle 是**临时**文件，用完即删；结论写进报告，不要留在 CI（落盘副作用不适合 CI）。
- 顺手变成**永久退役守卫**：断言「必须消失的东西确实不在」—— 元素 **+ 整段渲染文本里的关键词**。
  **只断言结构的话，词可以悄悄走回来。**

## 三、删 CSS：按规则删，不按文本删

正则一定会漏/误伤，因为这里同时存在五种结构：

1. 规则嵌在 `@media` 里（多一层）；
2. 逗号分组里**只有一个成员是死的**（`.a span, .b a { … }`）；
3. **一行里塞了十几条规则**；
4. **注释里点名了死类**；
5. **一条活规则写成取反**：`.page-shell:not(.is-agent-workspace)` —— 类永不应用 ⇒ 规则**恒真**，
   必须**简化**（→ `.page-shell`）而不是删除。

做法：

```
屏蔽注释（保留 offset 与换行）→ 括号配对解析成节点树 → 逐规则判定
→ 分组内只丢死成员（没丢就 continue，别产生空编辑）
→ 空掉的 at-rule 一并删，并吸收其上方「指名死类」的注释
→ 全部在内存里构造完 → 断言 → 最后才落盘
```

**解析器自检**（必须加，否则一个错位节点会静默切到邻居）：
每个节点满足 `text[preludeEnd] === "{"` 且 `text[nodeEnd - 1] === "}"`。

**落盘前断言**：无重叠编辑（`end > next.start` 就抛）、花括号配平、死类 0 残留、`result !== original`。

## 四、判死类的匹配（两个会静默漏掉的坑）

- **BEM 子类不能用 lookahead**：`\.name(?![\w-])` 里 `_` **是** word 字符 → `.name__child` 不匹配，
  整批子类会漏掉。必须显式判定：
  `token === name || token.startsWith(name + "__") || token.startsWith(name + "--")`。
- **`:not(.死类)` 里的类不算死**：先 `member.replace(/:not\([^)]*\)/g, "")` 再判，否则会把活规则当死规则删。

## 五、怎么证明删 CSS 是惰性的

「选择器永不匹配 ⇒ 规则无效果」是推理。要量两件事：

- **前提，在真浏览器里量**：遍历 `document.querySelectorAll("*")`，断言**没有任何元素**的 `classList`
  含这些类（含 `__`/`--` 变体）。多个视口下都应为空。
- **结论，computed style 差分**：对一组元素 × 一组视口，记录**一批计算属性 + 包围盒**，改前改后对比。
  实测 9 元素 × 4 视口 = 36 组、33 个属性 → 0 处差异。
  **视口要同时含「满足」和「不满足」相关媒体查询的尺寸** —— 只测命中态会漏掉
  「简化后原本落空的规则反而生效」。取反规则的 specificity 会从 `(0,2,0)` 掉到 `(0,1,0)`，这是真风险。

## 六、脚本会怎么骗你（比产品缺陷更难发现）

**变异/验证脚本**：

| 症状 | 真相 |
| --- | --- |
| 全部 GREEN | `execFileSync("npx", …, { shell: true })` **根本没跑起来**；spawn 失败 → 空输出 → 正则把「空」读成「没有失败」 |
| 仍 GREEN | 管道只捕到 ~2 KB，`Tests N failed` 汇总行被截断 |
| 仍 GREEN | 变异**其实红了**，只是红在**更靠前**的断言，而期望字符串写的是另一条 |

→ **（a）判红依据是进程退出码**，不是汇总行；**（b）「没输出」当异常抛**；**（c）「变异红了」还要确认
它红在*预期那条*断言上**；**（d）输出重定向到文件，别走管道**；**（e）脚本自己断言「改动真落地了」
和「真回滚了」**。

**清理脚本**：`overlapping edits` 那种断言不是形式主义 —— 实测它挡住了一次真实的 4 字符重叠
（`nodeStart` 把**前导空白**也算进去，而上一条规则的「向后吞空白」吞同一段）。

**跨语言核对 offset 前先确认单位**：Python 按**码点**、JS 按 **UTF-16 单元**。混着看会以为解析器错位。
**先给解析器加自检**，自检通过再把怀疑从「解析器坏了」转到「单位不同」。
